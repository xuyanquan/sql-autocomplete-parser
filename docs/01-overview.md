## 1.1 什么是 SQL 自动补全？

当你在 IDE 或数据库管理工具中编写代码时，输入几个字符后会弹出一个建议列表，帮助你快速完成代码输入——这就是**自动补全 (Autocomplete)**，也叫**智能提示 (IntelliSense)**。

### 日常示例

想象你在编写 SQL 查询：

```sql
SELECT * FROM users WHERE |
                         ^ 光标在这里
```

一个智能的 SQL 编辑器应该能够：

1. **理解上下文** - 知道你正在编写 WHERE 条件
2. **提供建议** - 显示 `users` 表的所有列名：`id`, `name`, `email`, `age`
3. **快速输入** - 按 Tab 或 Enter 即可插入选中的建议

### 自动补全的价值

| 场景 | 没有自动补全 | 有自动补全 |
|------|-------------|-----------|
| 记住表名 | 需要查文档或看数据库 | 自动提示可用表 |
| 记住列名 | 容易拼写错误 | 精确的列名建议 |
| 函数语法 | 需要查手册 | 显示函数签名和说明 |
| 语法错误 | 执行时才发现 | 实时提示错误 |
| 开发效率 | 慢，需要切换窗口 | 快，一气呵成 |

## 1.3 项目目标

本项目的目标是构建一个**生产级**的 SQL 自动补全解析器：

### 功能目标

```
✅ 核心功能
├── SQL 词法分析 (Tokenizer)
│   ├── 关键字识别 (70+ SQL keywords)
│   ├── 标识符解析 (表名、列名、别名)
│   ├── 字面量解析 (字符串、数字)
│   └── 位置追踪 (行号、列号)
│
├── SQL 语法分析 (Parser)
│   ├── SELECT 语句完整解析
│   ├── FROM / JOIN / WHERE 子句
│   ├── GROUP BY / ORDER BY / LIMIT
│   └── 残缺语句处理
│
├── 上下文分析 (Context Analyzer)
│   ├── 光标位置检测
│   ├── 可用表/列识别
│   ├── 别名解析
│   └── 上下文类型判断
│
├── 智能建议 (Suggestion Engine)
│   ├── 关键字建议
│   ├── 表名/列名建议
│   ├── 函数建议 (带文档)

└── 语法验证 (Validator)
    ├── 语法错误检测
    ├── 表/列存在性检查
    └── 修复建议生成
```

### 为什么选择手写解析器？

你可能会问：为什么不使用 ANTLR、PEG.js 等工具自动生成解析器？

**答案：自动补全场景的特殊性**

```
普通解析器的目标：
  输入: 完整、正确的 SQL 语句
  输出: AST 或执行结果

自动补全解析器的目标：
  输入: 残缺的、可能有错误的 SQL 片段 + 光标位置
  输出: 上下文相关的建议列表
```

手写解析器的优势：

1. **更好的错误恢复** - 可以精确控制遇到错误时的行为
2. **残缺输入友好** - 专门为不完整语句设计
3. **性能可控** - 避免不必要的语法树构建
4. **包体积小** - 不需要引入解析器运行时
